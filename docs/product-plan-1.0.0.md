# DataLayer Studio 1.0.0 产品方案

> 制定日期：2026-07-17。制定时基线：App Store 已上架 0.3.3，GitHub Release 最新 v0.3.4，`swift test` 524 项全绿，GitHub 无 open issue。
> 本方案是 1.0.0 里程碑的唯一总纲；执行中所有任务拆分、验收、发布都以本文为准。流程约定一律以根目录 `AGENTS.md` 为准。
> 若执行时仓库现状与本文不符，以当前可验证事实为准，并回头修订本文。

## 一、版本定位

**1.0.0 不加任何新功能。** 它是一个宣言版本：DataLayer Studio 的功能面已经完整（多轨时间线、遥测画布、精确对表、预设、双导出路径、CLI、四语言），1.0.0 要做的是把这套功能打磨到"最好用"——可靠、快、一致、上手即会，然后以正式版的姿态站上 App Store。

三句话概括标准：

1. **可靠**：正常使用一整个剪辑周期（导入 → 编辑 → 保存 → 重开 → 导出）不出现崩溃、数据丢失、状态错乱。
2. **快**：预览拖动跟手，长片/4K 素材下内存平稳，导出速度不回退。
3. **清晰**：每个操作有反馈，每个错误有出路，四语言文案一致专业，视觉风格统一。

### 明确不做（Feature Freeze 清单）

- ❌ 新仪表类型、新遥测字段、新图表样式
- ❌ iPhone 版（保持提案状态）；iPad 版继续独立节奏推进，**不并入 1.0.0 里程碑**，不阻塞也不搭车
- ❌ 新导出格式/编码器
- ❌ 云同步、账号体系、社区功能
- ❌ 任何"以后可能用"的抽象与重构

执行期间任何人（包括 AI 智能体）提出的新功能想法，一律记入 `docs/backlog-post-1.0.md`（没有就创建），不进 1.0.0。

### 不可触碰的红线（每个任务开工前重读）

- 免费版限制（1080p + 水印 + 购买引导）不得失效——`ExportEntitlement`、三个视频写出器、`PurchaseAuthorizationStore`。
- 透明 HEVC / ProRes Alpha 不得重新引入发灰问题；回归基线见 `docs/archive/qa-0.2.3-transparent-and-longform.md`。
- 视频写出必须逐帧流式，不得整段缓存。
- 布局字段 Codable 向后兼容，旧 preset / 旧 `.dlsproj` 必须能加载。
- 新增/修改 UI 文案必须四语言同步（`Localization.swift`，`LocalizationTests` 把关）。

## 二、工作流（六大打磨方向）

每个工作流 = 一个可独立分派给智能体的方向。执行顺序见第三节里程碑；同一里程碑内的工作流可并行。

### 工作流 A：已知体验债务清零

0.3.x 交接文档明确记录、一直推迟的三项，1.0.0 必须收口：

| # | 债务 | 出处 | 验收 |
| --- | --- | --- | --- |
| A1 | 复制时间线片段只写状态、无用户可见 toast | `docs/archive/handoff-0.3.3.md` 第二节 | 复制成功/失败均有 toast，四语言，有测试 |
| A2 | 完整视觉令牌体系（间距、字号、圆角、颜色收敛为 `ShellStyle` 令牌） | `docs/archive/ux-overhaul-0.3-plan.md` 4.9 | 全 GUI 无游离的魔法数字样式值；新增令牌有命名规范说明 |
| A3 | `controlSize` 分层（面板层级用系统 controlSize 区分主次） | 同上 | 检查器/侧栏/底部工作区层级清晰，四语言下不破版 |

A2/A3 是 1.0.0 里唯一允许的"大面积改 UI 代码"任务，必须放在 M2 集中做、逐视图小步提交，每步跑 `OverlayStudioTests` + `scripts/build_app_bundle.sh` 人工过目截图。

### 工作流 B：可靠性审计与修复

目标：把"不出错"变成被验证过的事实，而不是没人报过 bug。

- **B1 错误路径普查**：遍历 GUI 所有 `setStatus`/`setStatusAndToast`/错误分支，确认每个用户可感知的失败（文件损坏、磁盘满、权限拒绝、媒体离线、FIT 解析失败、导出中断）都有明确文案 + 出路（重试/定位文件/打开帮助）。产出一份清单文档，逐项打勾。
- **B2 数据安全**：工程保存写入必须原子（临时文件 + 替换）；崩溃/强退后重开工程不丢最后一次显式保存；验证自动保存/恢复行为并写入手册。
- **B3 边界输入**：0 字节 FIT、只有 1 条记录的 FIT、跨午夜活动、暂停超长的活动、时长为 0 的视频、变帧率视频、超长（>3h）视频——每类至少一个测试或记录明确的拒绝行为。
- **B4 撤销/重做完整性**：时间线所有可变更操作（移动、裁剪、分割、锁定、删除、粘贴、对表偏移）逐项验证 undo/redo 成对可逆，补齐缺失测试。
- **B5 免费版路径回归**：GitHub 直下、自编译、CLI 三种形态各走一遍完整导出，确认水印、1080p 钳制、购买引导全部生效。

### 工作流 C：性能打磨

以 `docs/archive/render-performance-optimization.md` 为基线，只做有测量依据的优化：

- **C1 建立基准**：用 `assets/resourses/` 本机素材固化一组基准场景（1080p 短片、4K 长片、密集仪表布局），记录预览帧率、导出耗时、峰值内存到 `docs/perf-baseline-1.0.md`。此后任何性能任务必须给出前后对比。
- **C2 预览跟手性**：播放头拖动、片段拖动、检查器数值调整时预览延迟可感知的场景，逐个定位修复（配合 `swiftui-performance` 方法论：先测量后动手）。
- **C3 内存红线**：4K 长片导出全程内存平稳（无线性增长）；用 C1 基准验证。
- **C4 启动与加载**：冷启动到可交互、打开大工程的耗时测量；只修显著慢的点，不为数字而优化。

### 工作流 D：首次体验与文案

目标：一个从未用过的跑者，不看手册 10 分钟内导出第一条浮层。

- **D1 首次运行动线走查**：欢迎窗 → 新建工程 → 拖入素材 → 对表 → 导出，每一步的空状态、引导文案、默认值逐项评审；产出问题清单再修。
- **D2 空状态设计**：无视频只有 FIT、无 FIT 只有视频、空时间线、空预设列表——每个空状态都要告诉用户"下一步做什么"。
- **D3 四语言文案审计**：全量过一遍 `Localization.swift` 四套文案：术语一致（如"对表/同步"、"片段/剪辑"只用一个）、无机翻腔、标点风格统一。英文和日文建议各由独立智能体以母语者标准复审。
- **D4 键盘与菜单**：主菜单项完整（撤销/重做/保存/导出均有标准快捷键）、常用操作有快捷键并在菜单可见；macOS 系统级惯例（⌘S、⌘Z、space 播放）全部符合。
- **D5 无障碍基线**：关键控件有 accessibility label，预览画布之外全键盘可达。不追求满分，追求 App Store 正式版不失格。

### 工作流 E：兼容性与 CLI 对齐

- **E1 升级兼容矩阵**：用 0.2.x、0.3.x 各留一份 preset 与 `.dlsproj` 样本（存入 `Tests/` fixture），加载测试进 CI，永久防回归。
- **E2 CLI/GUI 一致性**：同一工程 + 同一预设，CLI 与 GUI 导出结果逐帧一致（抽样比对）；CLI `--help` 文档与实际行为无出入。
- **E3 手册与产品同步**：`docs/user-guide/` 四语言手册逐节对照 1.0.0 实际界面更新截图与描述，重新生成网页版并部署。

### 工作流 F：发布工程

- **F1 版本策略**：下一个发布版本即 1.0.0；App Store 与 GitHub Release 同步该版本号。
- **F2 App Store 素材焕新**：以 1.0.0 定稿界面重拍四语言截图（`assets/appstore/v1.0.0/`）；加载 `app-store-optimization` skill 复审名称/副标题/关键词/描述；What's New 以"正式版 1.0"为叙事。
- **F3 落地页与 README**：落地页、双语 README 更新为 1.0.0 叙事（正式版、稳定承诺、免费版说明不变）；按 AGENTS.md 部署 `landing-page` 分支。
- **F4 RC 流程**：M3 冻结后出 RC 构建走内部 TestFlight，至少完整跑一遍第五节验收清单；RC 期只收阻塞级修复。
- **F5 正式发布**：按 AGENTS.md 既有流程执行 TestFlight → 提审（`AFTER_APPROVAL`）→ GitHub `v1.0.0` tag → release workflow → 下载资产脱沙箱三重验证 → Release 正文含 Highlights、带链接 commit 列表、免费版说明与 App Store 购买链接。

**待用户决策（不阻塞 M0–M2，M3 前需要答案）**：早鸟价是否随 1.0.0 正式版结束/调价？涉及落地页定价区与 ASC 价格，属于用户决定事项，AI 团队不得自行改动。

## 三、里程碑与执行顺序

```
M0 审计（并行铺开）→ M1 修复 → M2 一致性打磨 → M3 冻结与 RC → M4 发布
```

| 里程碑 | 内容 | 出口条件 |
| --- | --- | --- |
| **M0 审计** | B1/B3/B4 普查、C1 性能基准、D1/D2/D3 走查审计、E1 样本收集。只产出清单和基准，不动刀 | 各审计清单文档合入 main，问题按 P0（数据丢失/崩溃/红线）、P1（明显体验缺陷）、P2（打磨项）分级 |
| **M1 修复** | 修完全部 P0/P1；A1、B2、B5、C2/C3、E2 在此完成 | P0/P1 清零；`swift test` 全绿；基准对比无回退 |
| **M2 一致性** | A2 视觉令牌、A3 controlSize、D3 文案落地、D4/D5、E3 手册同步、P2 择优 | GUI 视觉/文案审计复查通过；四语言截图预检无破版 |
| **M3 冻结与 RC** | 代码冻结，F2 截图、F4 RC + TestFlight、全量验收清单 | 第五节验收清单全项通过；RC 无未决阻塞项 |
| **M4 发布** | F5 正式发布 + F3 落地页 | App Store 1.0.0 上架、GitHub v1.0.0 资产验证通过、手册/落地页/README 全部同步 |

M0 各审计互不依赖，可同时分派多个智能体；M1 起修复任务按文件冲突面拆分，避免两个智能体同时改 `ProjectTimelineView.swift` 这类大文件。

## 四、AI 团队任务分派规则

给每个智能体下发任务时，指令中必须包含：

1. **锚点**：本文档路径 + 所属工作流编号（如 B3）+ 明确的验收标准。
2. **约束**：先读 `AGENTS.md`；开工前 `git fetch` 确认不落后；只动任务必须触及的文件；不顺手重构。
3. **验证**：任务对应的最小测试集（见 AGENTS.md 测试命令节）+ 影响 GUI 时跑 `scripts/build_app_bundle.sh`。
4. **提交**：简体中文提交信息，格式沿用现有历史（`需求：…｜实现：…` / `问题：…｜修复：…`）；完成后 push 并在回复中报告改了什么、验证了什么、剩余风险。
5. **越界处理**：发现超出任务范围的问题，记录到对应审计清单，不就地扩大范围；发现新功能想法进 `docs/backlog-post-1.0.md`。

审计类任务（M0）额外要求：产出物是文档不是代码；每个问题必须给出复现步骤或代码位置（`文件:行号`），并给出 P0/P1/P2 分级建议，最终分级由用户裁定。

## 五、1.0.0 验收清单（Definition of Done）

发布前逐项核对，全部通过才允许提审：

**功能回归**
- [ ] `swift test` 全量通过
- [ ] 完整用户旅程人工走查：新建工程 → 导入视频+FIT → 对表 → 摆仪表 → 存预设 → 保存工程 → 重开 → 导出透明浮层 + 合成视频，四语言各走一遍关键路径
- [ ] 0.2.x / 0.3.x 旧 preset 与旧工程文件加载正常（E1 自动化测试 + 人工抽查）
- [ ] CLI 与 GUI 同预设导出结果一致（E2）
- [ ] 免费版三形态（GitHub 包 / 自编译 / CLI）水印与 1080p 钳制生效，购买引导可点（B5）

**质量红线**
- [ ] 透明 Alpha 边缘无发灰（对照 0.2.3 QA 基线）
- [ ] 4K 长片导出内存平稳（对照 C1 基准）
- [ ] 性能基准三场景无回退（C1 对比报告）
- [ ] 崩溃/强退后重开不丢已保存数据（B2）

**体验与一致性**
- [ ] A1/A2/A3 三项债务收口
- [ ] 错误路径清单（B1）逐项有文案有出路
- [ ] 四语言文案审计（D3）问题清零，`LocalizationTests` 通过
- [ ] 空状态（D2）与快捷键（D4）走查通过

**发布物**
- [ ] 四语言手册与网页版同步 1.0.0（E3）
- [ ] App Store 四语言截图/元数据焕新且 validate 通过（F2）
- [ ] GitHub Release 资产脱沙箱三重验证通过（codesign / stapler / spctl）
- [ ] 落地页、双语 README 同步 1.0.0（F3）

## 六、风险与对策

| 风险 | 对策 |
| --- | --- |
| A2/A3 大面积改 UI 引入回归 | 限定在 M2、逐视图小步提交、每步构建走查；改动不碰状态逻辑只碰样式层 |
| 审计产出的问题清单失控膨胀 | 分级裁定权在用户；P2 只在 M2 有余量时做，做不完随 1.0.1 |
| 多智能体并行改同一大文件冲突 | 分派时按文件划界；大文件任务串行 |
| 性能优化引发行为变化 | 一律先建基准后动手，导出结果做前后逐帧抽样比对 |
| 冻结后忍不住塞新功能 | Feature Freeze 清单 + backlog 机制；Release 叙事以"稳定与打磨"为卖点，不需要新功能撑场面 |

## 七、1.0.0 之后

本方案不规划 1.x 功能路线。发布后：`docs/backlog-post-1.0.md` 里积累的想法 + iPad 版进度 + 用户反馈，另立方案裁定。本文档在 1.0.0 上架后移入 `docs/archive/` 并加归档说明。
