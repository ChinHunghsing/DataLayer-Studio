# 0.1.5 UI/UE Workbench Optimization Plan

## 当前状态（2026-07-05）

阶段 1-4 已完成，DataLayer Studio 的主界面已经从“左侧流程表单”改成更接近剪辑工作台的结构：

- 左侧是 Project Panel：素材、画布、预设、iCloud 状态。
- 中间是 Preview Stage：视频预览、gauge 拖动、播放控制。
- 预览下方是 Bottom Workspace：同步、裁剪、输出。
- 右侧是 Inspector：只编辑当前选中的 gauge。
- 窗口顶部中间显示当前视频文件名，无视频时显示 FIT/GPX 文件名。

阶段 1-4 之后又补过几轮小优化，也纳入当前基线：

- 素材加载后默认进入“同步”页。
- 导出进度和导出结果改为弹窗显示。
- 导出按钮布局已经单独压到底部输出页。
- 裁剪范围支持当前时间设为开始/结束。
- 预览时间限制到导出区间。
- 运动开始时间提示已优化。
- Inspector 已有分段筛选、展开/折叠、选中元素头部操作、空状态和隐藏元素提示。
- 菜单里已有打开、导出、取消导出、播放/暂停、标记运动开始、缩放、全屏、层级前后移动；画布已有方向键微调。

## 可用 Skills 路线

本轮不用一口气开所有设计技能。按问题类型用最小组合：

| Skill | 用途 | 使用时机 |
| --- | --- | --- |
| `critique` | UI/UE 审核、发现阻塞问题 | 每轮 UI 改动前后各跑一次轻量审查 |
| `shape` | 把模糊问题收束成小范围设计 brief | 新增交互前，尤其是 Inspector/快捷流 |
| `build-macos-apps:swiftui-patterns` | macOS 桌面结构、commands、Inspector、split layout | 修改窗口结构、菜单、快捷键、Inspector 时 |
| `layout` | 间距、密度、视觉层级 | Bottom Workspace 和 Inspector 二次打磨 |
| `clarify` | 文案、错误、空状态、提示 | 同步、导出、权限、天气 API key、空状态 |
| `adapt` | 小窗口、长文本、多语言适配 | 英中繁日四套文案落地后 |
| `polish` | 最终一致性和细节检查 | 每个阶段收尾 |
| `swiftui-expert-skill` | SwiftUI 状态、性能、焦点、可访问性 | 出现性能/焦点/无障碍问题时再用 |

备注：`.impeccable.md` 当前不存在。如果要继续做更主观的视觉风格升级，先跑 `impeccable teach` 补项目设计上下文；本计划先按现有产品约定收束，不额外改品牌方向。

## 设计判断

DataLayer Studio 现在的主要问题不是“大重构不够”，而是 1-4 完成后，几个工作区还缺最后的可发现性、密度控制和状态反馈。继续沿用现有结构，优先修用户实际会卡住的点：

- 新用户：不知道下一步该同步、裁剪还是输出。
- 熟练用户：已有快捷键和菜单，但 UI 里不够明显。
- 调 gauge 的用户：Inspector 功能已经全，但高频调节仍然埋在较深层级里。
- 导出用户：现在有进度弹窗，但导出前的可执行/不可执行原因还可以更直接。

## 阶段 5：Inspector 二次打磨

目标：保留现有 Inspector 架构，只让高频操作更快、更清楚。

优先改：

- 保留当前分段筛选，不再重做 Inspector 导航。
- 让选中元素头部继续承担高频动作：添加、显示/隐藏、复制、层级、删除。
- 检查布局、内容、外观、字体、数据五组的顺序和默认展开状态，避免一进来就需要滚很久。
- 每个折叠组的摘要只保留真正有决策价值的信息，避免摘要比内容还吵。
- 隐藏元素提示保留在顶部，确保“看不见但选中了”的状态能被解释。

暂不做：

- 不新增全局 Inspector 状态模型。
- 不新增一套 preset/模板系统。
- 不把所有属性做成批量编辑。

推荐技能：`layout` + `build-macos-apps:swiftui-patterns`，收尾用 `polish`。

## 阶段 6：Bottom Workspace 流程提示

目标：用户在同步、裁剪、输出之间移动时，不靠猜。

优先改：

- 同步页：保留当前“运动开始”主动作，补清楚当前视频时间和运动时间的关系。
- 裁剪页：让“当前为开始/当前为结束/完整范围”在视觉层级上比数字摘要更明显。
- 输出页：导出不可用时，把共享 readiness message 放在按钮附近，不只放在 help tooltip。
- 导出页：继续保留两个明确出口：透明浮层、合成视频；FIT/GPX-only 时合成视频继续禁用。
- Tab 切换逻辑保持简单：加载素材后默认同步，不新增自动跳来跳去的流程引擎。

暂不做：

- 不引入 wizard。
- 不把同步、裁剪、输出拆成独立窗口。
- 不让导出设置回到左侧。

推荐技能：`clarify` + `layout`，必要时用 `shape` 收束文案和层级。

## 阶段 7：快捷操作和可发现性

目标：已有快捷键不白做，让桌面用户能发现并信任它们。

优先改：

- 盘点现有命令菜单，补缺的关键动作即可。
- 在按钮 tooltip/help 里统一显示快捷键，不新增可见说明区。
- 检查命令是否只注册一次，避免快捷键冲突。
- 保持关键动作同时有 UI 路径和菜单路径：打开素材、播放、标记运动开始、导出、取消导出、缩放、全屏、层级移动。
- 如果补裁剪快捷键，优先复用现有 `setExportTrimStart` / `setExportTrimEnd`，不要绕开 `StudioModel`。

暂不做：

- 不做完整快捷键设置页。
- 不做自定义快捷键。
- 不把 Debug 命令搬进主界面。

推荐技能：`build-macos-apps:swiftui-patterns`，文案用 `clarify`。

## 阶段 8：状态、空状态、错误恢复

目标：让用户在没素材、素材失败、导出失败、导出完成时都知道下一步。

优先改：

- Project Panel 的视频/FIT 加载失败行继续保留 retry，但检查四语言文案是否足够具体。
- Inspector 空状态聚焦“先选一个 gauge 或添加 gauge”，不要写成说明书。
- 输出页导出完成后的弹窗保留 Finder 和打开文件动作。
- 导出失败显示用户能采取的下一步，避免只露底层错误。
- 天气 API key 区域继续放在 weather gauge 的 data section，不移到全局设置，除非后续发现多处都要用。

暂不做：

- 不新增 help center。
- 不新增 onboarding。
- 不新增全局 toast 系统。

推荐技能：`clarify`，收尾用 `polish`。

## 阶段 9：小窗口、多语言和可访问性适配

目标：1320×760 最小窗口内不挤爆，四语言长文本不破版，键盘和 VoiceOver 基础可用。

优先改：

- 用英文、简中、繁中、日文检查 Bottom Workspace tab、Inspector 头部、导出弹窗、错误行。
- 检查长文件名：窗口标题、导出结果、保存位置都要中间截断或换行合理。
- 检查小窗口下 Inspector action group 是否落入 menu，而不是挤压标题。
- 保持触控目标和 icon button 尺寸稳定，不因文案变长改变布局。
- 对新增交互补 accessibility label/help。

暂不做：

- 不做移动端适配。
- 不改最小窗口尺寸，除非实际验证发现 1320×760 已经不够。

推荐技能：`adapt` + `polish`，SwiftUI 焦点问题再用 `swiftui-expert-skill`。

## 验证策略

每个阶段按最小可跑验证：

- 文档或纯计划更新：不跑构建。
- UI 可见行为改动：运行 `scripts/build_app_bundle.sh`。
- 改 UI 状态、导出设置、预设、天气：至少跑相关 `OverlayStudioTests`。
- 改菜单/快捷键：手动检查菜单项 enabled/disabled，并跑 app bundle。
- 改导出路径、透明 Alpha 或视频写出：额外跑对应 writer/renderer 测试，避免透明灰底回归。
- 每次提交前：`git fetch`，确认当前分支不落后，`git status --short` 只包含本次文件。

## 优先级

1. 阶段 5：Inspector 二次打磨。
2. 阶段 6：Bottom Workspace 流程提示。
3. 阶段 7：快捷操作和可发现性。
4. 阶段 8：状态、空状态、错误恢复。
5. 阶段 9：小窗口、多语言和可访问性适配。

最小路线：先做阶段 5 和阶段 6。它们覆盖当前工作台最大的剩余摩擦；阶段 7-9 可以跟随实际改动拆小提交。
