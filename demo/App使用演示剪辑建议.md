# App 使用演示剪辑建议

本文对应 `App使用演示.mov`。原视频时长为 `00:57:56.303`，没有音轨。

## 主要问题

有效操作集中在前 `10:23` 和最后约 21 秒。`00:10:23–00:57:35` 基本都是导出进度等待，约 47 分 12 秒，占全片约 81%。此外，`00:00:51–00:09:50` 多次重复拖动播放头检查不同片段，说明价值相近，也可以进一步压缩。

## 最低风险剪法

这种剪法只删除纯等待，不改变前面的实际操作流程：

| 原视频时间码 | 处理 |
| --- | --- |
| `00:00:00–00:10:23` | 保留导入、检查和开始导出的完整操作 |
| `00:10:23–00:57:35` | 删除导出等待 |
| `00:57:35–00:57:56.303` | 保留进度完成、完成提示和返回工程 |

在 `00:10:23` 与 `00:57:35` 之间使用直接切换，或加入 0.3–0.5 秒叠化。切点处增加一张 2–3 秒的提示卡：

> 正在导出透明浮层……实际耗时取决于视频时长、分辨率和电脑性能。

这样成片约 10 分 44 秒，已经可以去掉绝大部分无效等待。

## 推荐的紧凑剪法

建议把成片控制在 3–4 分钟。保留每类操作的一个代表画面，不必完整展示每一次播放头拖动。

| 原视频时间码 | 建议处理 | 要表达的内容 |
| --- | --- | --- |
| `00:00:00–00:00:04` | 保留 | 选择素材入口 |
| `00:00:04–00:00:20` | 加速至 2–3 倍 | 选择并读取多段原始视频 |
| `00:00:20–00:00:34` | 保留 | 继续选择 FIT/GPX，并完成自动对齐 |
| `00:00:34–00:01:15` | 保留或轻微加速 | 认识媒体池、V1/O1 时间线和第一段预览 |
| `00:01:15–00:03:00` | 压缩到约 25 秒 | 展示短片段、空白区和下一段视频的检查方法 |
| `00:03:00–00:06:00` | 压缩到约 30 秒 | 选取两三个代表位置，展示数据连续变化 |
| `00:06:00–00:09:15` | 压缩到约 30 秒 | 展示黑底空白区、片段交界和后段素材检查 |
| `00:09:15–00:09:50` | 压缩到约 10 秒 | 最终布局复核 |
| `00:09:50–00:10:23` | 保留 | 输出设置与开始导出 |
| `00:10:23–00:57:35` | 删除 | 长时间导出等待 |
| `00:57:35–00:57:56.303` | 保留 | 导出完成和返回工程 |

## 推荐的画面处理

- 对重复拖动播放头的区间使用 3–6 倍速，并在速度变化处加入简短的“检查各片段同步”提示。
- 不要把导出等待整体做成几十倍速：即使加速，画面仍然单调。保留开始的 2–3 秒和结束的 5–8 秒，中间直接删除更清楚。
- 在跳过导出等待的位置加入时间跳转提示，例如“约 47 分钟后”。
- 导出完成后保留“导出完成”窗口至少 3 秒，让观众能看清文件名和“在访达中显示”“打开”“完成”三个操作。
- 如果要配合旁白，完成剪辑后应根据新时间线重新生成 SRT；当前 `App使用演示说明.srt` 对应的是未经剪辑的原视频时间码。

## 建议成片结构

1. 导入多段视频和运动文件。
2. 展示自动对齐后的媒体池与时间线。
3. 用少量代表片段说明如何检查同步和布局。
4. 打开输出面板，确认透明浮层导出设置。
5. 跳过等待，展示导出完成。

这套结构既保留完整方法，也能避免观众把大部分时间花在重复检查和等待进度上。
