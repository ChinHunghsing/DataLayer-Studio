## 0. 结论摘要

iPhone 版在技术上与 iPad 版共享同一套可行性结论（核心引擎零改动复用，见 iPad 技术文档 §0）。但产品形态必须不同：**iPhone 版不是把三栏编辑器塞进小屏，而是「口袋里的赛后出片工具」**——视频在手机相册里、FIT 在手机 Files 里、发布目标是手机上的社交 App，闭环本来就长在手机上。iPhone 版做「模板优先、轻编辑、快分享」，深度定制留给 iPad/Mac，预设经 iCloud 打通三端。

## 1. 背景与机会

跑者的素材链路天然经过 iPhone：

- 视频：自己或亲友用 iPhone 拍摄，或运动相机回传到手机相册；
- 数据：手表 FIT 文件通过 Garmin Connect / COROS / 高驰等 App 或 Files 到达手机；
- 发布：Instagram / 小红书 / 抖音 / Strava，全部在手机完成。

现状是用户必须把素材搬去 Mac 做浮层再搬回手机发布。iPhone 版把这条链路缩短为「拍完/跑完 → 手机上 5 分钟出片 → 直接分享」。同时 iPhone 版是三端矩阵的流量入口：App Store 上 iPhone 曝光远大于 Mac，轻量出片吸引的用户会向 iPad/Mac 深度编辑迁移——一次购买三端使用，中间没有任何付费墙。

## 2. 产品定位

一句话：**跑完当天，在手机上把数据层套上视频、直接发出去。**

与 iPad/Mac 版的分工：

| | iPhone | iPad / Mac |
| --- | --- | --- |
| 核心动作 | 套模板 → 微调 → 导出分享 | 从零排布、逐组件深度定制、做模板 |
| 主要产物 | 合成成片（直接可发） | 透明浮层（进专业剪辑）+ 成片 |
| 编辑深度 | 轻编辑（位置/缩放/主题色/显隐/单位） | 全量（字体、面板、刻度、精度、逐色…） |
| 预设角色 | 消费端（套用三端同步的模板） | 生产端（制作与维护模板） |

「轻编辑」是删交互不是删引擎：渲染结果与 iPad/Mac 完全一致，同一预设三端渲染像素级相同。

### 非目标（v1 不做）

- 完整检查器（逐组件全量定制项）——只暴露高频子集，其余提示「在 iPad/Mac 上编辑此预设」。
- 透明浮层工作流的深度支持（保留导出能力，但不是主路径）。
- HealthKit / Watch 直接导入（远期，见开放问题）。
- 拍摄功能。本 App 不做相机。

## 3. 目标用户与场景

画像沿用 Alex / Jordan / Sam（见 iPad 产品文档 §3），iPhone 侧的典型场景：

1. **赛后即刻发**（主场景）：完赛后在返程地铁上，从相册选亲友拍的冲线视频，从 Garmin Connect 分享 FIT 给 DataLayer Studio，自动按开始时间对齐，套「比赛回顾」模板，拖一下配速表位置，导出 1080p 成片存相册，发小红书。
2. **竖屏短片**：日常训练 15 秒竖拍，套 9:16 竖版模板（心率+配速+路线三件套），导出直接发 story。
3. **给剪辑软件备料**（次场景）：老手在手机上快速出一版透明浮层，AirDrop 给 Mac 上的 FCP 精剪。

## 4. 核心流程

### 4.1 首次/新项目：三步向导

```
[1 选视频]  →  [2 选活动数据]  →  [3 对齐]
 相册/Files      Files/打开方式        自动对齐 + 微调
```

- 每步一屏，大按钮；已有素材时可跳步。
- 第 3 步默认执行**自动对齐**：用视频拍摄时间元数据与 FIT 绝对时间戳求初始偏移（新增能力，三端受益），给出「看起来对齐了吗」的预览确认页，允许 ±帧微调；复杂情况入口「高级对齐」提供与 Mac 相同的三模式。

### 4.2 主编辑页

```
┌─────────────────────────┐
│ ◀ 项目名        导出 ⬆︎  │  ← 顶栏
│                         │
│      预览画布            │  ← 视频 + 浮层，手势编辑
│   （按视频宽高比适配）      │
│                         │
│  ──●────────────  ▶      │  ← 时间轴 + 播放
│ [模板] [组件] [对齐] [设置] │  ← 底部工具条
└─────────────────────────┘
```

- 底部工具条四项均弹**半高 sheet**（可上拉全高），画布始终可见：
  - **模板**：预设横向卡片流（含 iCloud 同步的自有预设 + 内置模板），点击即套用，可撤销。
  - **组件**：当前布局组件清单（显隐开关、添加组件）；选中组件后 sheet 切换为**轻量检查器**：主题色、大小、透明度、显隐标签/单位、（组件相关的 1–2 个高频项，如路线线宽、仪表上限）。
  - **对齐**：偏移微调（±1 帧 / ±1 秒步进）、重新自动对齐、高级对齐入口、「设为运动开始」打点按钮。
  - **设置**：单位、语言、外观、天气 key、关于。
- 画布手势：点选组件 → 拖动移动（44pt 起步热区 + 选中放大热区）→ 双指捏合缩放选中组件（注意：与 iPad 不同，捏合优先作用于**选中组件的缩放**，画布缩放通过双击切换适配/100%，small viewport 下画布平移需求弱）。

### 4.3 导出页

- 一屏完成：产物类型（成片 / 透明浮层——次要位置）、画质（1080p / 4K / 跟随源）、区间（快捷「全片/最近30秒/自选」）、预估大小。
- 帧率/码率/自定义分辨率折叠进「高级」。
- 导出中：进度 + ETA + 取消，屏幕常亮，显著提示「请保持 App 打开」；（远期）灵动岛/锁屏 Live Activity 显示进度。
- 完成页：大预览 + 「存入相册」「分享」「存到 Files」（浮层默认 Files）+「再导一版」。

## 6. 内置竖版模板（v1 新增内容资产）

- 背景：现有默认布局按 16:9 设计；归一化坐标在 9:16 画幅下比例失衡（组件相对宽度过大、横向排列溢出）。iPhone 主力产出是竖屏，**必须提供竖版原生模板**，否则首次体验破碎。
- v1 交付：9:16 竖版 2–3 套（极简三件套 / 数据密集 / 路线主视觉）、1:1 方形 1–2 套、16:9 沿用现默认。模板由设计产出为标准 LayoutPreset JSON，作为内置资源随 App 分发（不占用户 iCloud 配额）。
- 模板卡片按当前视频宽高比排序推荐（竖屏视频优先展示竖版模板）。

## 7. 导出与分享体验

- 成片存相册为默认动作（add-only 权限）；分享走系统分享面板（IG/小红书/抖音等由系统接管）。
- 透明浮层 .mov 默认存 Files 并提示「用于 Final Cut / DaVinci 等剪辑软件」；不向相册写浮层（相册预览黑底误导用户）。
- 约束沟通：导出前按「时长 × 分辨率」给出预估耗时区间；机身发热时显示提示（不阻断）；低电量模式下提示可能变慢。
- 失败与中断永远可解释、可重试（沿用「错误预防且解释」原则）。

## 8. 无障碍与本地化

- VoiceOver：画布组件保持 label/value/hint/自定义操作；底部 sheet 的 detent 变化保证焦点不丢失。
- 触控目标 ≥ 44pt；拖动支持替代方式（选中后用步进按钮移动，供运动障碍用户）。
- 动态字体：全部面板文案支持；画布渲染产物除外（同 iPad 文档说明）。
- 四语言（en/zh-Hans/zh-Hant/ja）零缺失，沿用 AppLocalizer。

## 9. 商业化与发布

- **商业模式（已定）：与 Mac / iPad 统一定价，一次购买三端使用（Universal Purchase，同一 App record）。** iPhone 与 iPad 本就是同一个 iOS App；Mac 版经 Universal Purchase 挂接，已购用户在任一端购买后三端直接解锁（工程细节见 iPad 技术文档 §9）。
- iPhone 是 App Store 获客主入口：统一定价下，iPhone 端的转化直接抬高三端用户基数；截图脚本围绕场景 1（赛后出片）与场景 2（竖版模板）设计；关键词围绕 running overlay / 跑步数据视频 / FIT。
- 审核注意：天气功能要求用户自备 OpenWeather key，需在设置文案中说明用途，避免被认作未完成功能；「在 iPad/Mac 上编辑此预设」的引导指向同一次购买内的能力，不构成诱导升级。

## 10. 成功指标

| 指标 | 目标 |
| --- | --- |
| 首启 → 首次导出转化 | ≥ 40%（向导流程的核心考核） |
| 首次导出中位耗时 | ≤ 5 分钟 |
| 导出成功率 | ≥ 99%（含中断重试成功） |
| 竖版模板使用率（竖屏视频项目中） | ≥ 70% |
| 分享/存相册完成率（导出成功后） | ≥ 80% |
| 崩溃率 | < 0.3% 会话 |

## 12. 开放问题

1. 自动对齐的精度目标与兜底：视频创建时间元数据缺失/时区错乱时的策略（估计相当常见，需真实素材样本库验证）。
2. 轻量检查器暴露的定制项清单最终裁定（建议以 Mac 版使用频率数据/直觉先定 8–10 项，TestFlight 反馈迭代）。
3. HealthKit 导入（免 FIT：Apple Watch 用户直接选一次训练）是否提前——对 iPhone 用户价值最大，但涉及新权限与数据映射，建议 v1.x 首个功能更新。
4. Live Activity 导出进度是否进 v1（技术上独立，砍不影响主线）。
5. 内置模板是否随版本更新扩充为「模板库」（内容运营成本 vs 留存价值）。
