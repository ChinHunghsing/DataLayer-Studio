# DataLayer Studio 1.0.0 产品方案

> 方案版本：v2，2026-07-18。替代 2026-07-17 的初稿。
> 校订基线：本地 `main` 与 `origin/main` 同步；GitHub Release 最新为 v0.3.4；GitHub 无 open issue；最新 `main` CI 通过。App Store 当前版本沿用仓库记录的 0.3.3，发布阶段必须再用 ASC 实查。
> 本文只定义 1.0.0 的产品范围和发布门槛；通用开发、测试、签名与发布流程以根目录 `AGENTS.md` 为准。

## 一、修订结论

1. **保留方向**：1.0.0 是可靠性与完成度版本，不靠新增功能撑版本号。
2. **收缩范围**：取消“全 GUI 清零魔法数字”一类无边界重构，只修审计中可复现、影响用户的视觉与交互问题。
3. **纠正现状**：工程保存已经使用原子写入；1.0.0 验证并守住现状，不临时新增自动保存或崩溃恢复系统。
4. **改写验收**：编码产物不要求字节级一致；GUI 与 CLI 比较输入、时长、分辨率、帧数、水印和抽样画面。
5. **减少文档先行**：审计与修复可在同一小任务闭环，不先堆一批长期失真的清单。

## 二、版本定位

1.0.0 的承诺只有三条：

- **不丢**：已明确保存的工程可重开，旧工程与旧预设可继续使用，导出限制不会被绕过。
- **不错**：主流程无崩溃、卡死、错误结果或无反馈失败；透明 Alpha、合成导出和时间同步不回退。
- **不慢**：相同机器和素材下，候选版相对 v0.3.4 没有可解释不了的性能回退。

### Feature Freeze

1.0.0 不新增：

- 仪表类型、遥测字段、图表样式；
- 导出格式或编码器；
- 云同步、账号、社区、插件；
- iPhone 功能；iPadOS 继续独立推进，不并入也不阻塞 macOS 1.0.0；
- 自动保存、崩溃恢复等新的工程系统；
- 为“以后可能用”准备的抽象或重构。

新想法只记录到 `docs/backlog-post-1.0.md`；没有实际想法时不创建空文件。

### 红线

- 免费版继续执行 1080p 上限、`Made with DataLayer Studio` 水印和 Mac App Store 完整版购买引导；覆盖 GitHub 包、自编译 GUI 与 CLI。
- 透明 HEVC / ProRes Alpha 不得重新发灰；以 `docs/archive/qa-0.2.3-transparent-and-longform.md` 为回归基线。
- 视频写出继续逐帧流式处理，内存不得随时长线性增长。
- 旧 `.dlsproj` / `.dlspreset` 必须可加载；Codable 变更保持向后兼容。
- 用户可见文案保持英文、简体中文、繁体中文、日文四语言同步。

## 三、必做范围

### R：可靠性

| 编号 | 工作 | 验收 |
| --- | --- | --- |
| R1 | 守住工程数据 | 现有原子保存有回归测试；显式保存后强退并重开，内容完整；保存失败不覆盖旧文件 |
| R2 | 旧版本兼容 | 从 v0.2.3、v0.3.4 生成最小工程与预设 fixture，CI 验证加载与关键字段 |
| R3 | 主错误路径 | 工程打开/保存、媒体导入/重链接、FIT 解析、导出失败均有用户可见结果；只有存在可执行恢复动作时才提供重试或引导 |
| R4 | 时间线可逆性 | 移动、裁剪、分割、锁定、删除、粘贴、对表偏移的 undo/redo 成对验证；只补缺失覆盖 |
| R5 | 免费版守卫 | entitlement 单测通过；免费 GUI 实际导出验证 1080p + 水印 + 购买入口；CLI 验证限制与购买链接文案 |

### U：体验与一致性

| 编号 | 工作 | 验收 |
| --- | --- | --- |
| U1 | 复制片段反馈 | 复制成功显示 toast；不可复制时菜单保持禁用，不制造不存在的“失败”分支；四语言与测试齐全 |
| U2 | 首次使用主路径 | 清空偏好后，以固定本机素材完成“新建 → 导入 → 对表 → 添加组件 → 保存 → 重开 → 导出”；简体中文完整走一遍，其余三语言检查布局和关键文案 |
| U3 | macOS 基本惯例 | ⌘S、⌘Z/⇧⌘Z、⌘E、空格播放及对应菜单可用；文本输入焦点下不误触编辑器快捷键 |
| U4 | 无障碍底线 | 主路径上的图标按钮有可读标签；非画布主操作可用键盘完成；只修明确缺口 |
| U5 | 定向视觉收口 | 只处理审计截图中可见的层级、截断、拥挤和四语言破版；复用现有 `ShellStyle`，不做全量令牌迁移 |
| U6 | 核心文案审校 | 统一“对表/片段/工程/导出”等主路径术语；不把整份本地化字典重写成翻译项目 |

### P：性能与输出

| 编号 | 工作 | 验收 |
| --- | --- | --- |
| P1 | 固定基准 | 同一台 Mac、release 构建、同一素材和设置，对比 v0.3.4 与 RC；记录导出耗时、峰值内存和打开工程耗时 |
| P2 | 回退判定 | 任一关键指标回退超过 10% 时必须复测；复测仍成立则修复或给出用户可感知不到的明确原因，由用户裁定是否接受 |
| P3 | 长片内存 | 4K 长片透明与合成导出各跑一次，内存无持续线性增长，导出可正常结束 |
| P4 | 输出正确性 | 透明 Alpha 肉眼与基线对照；GUI/CLI 同工程导出对比时长、尺寸、帧数、水印，并抽样首/中/末画面 |

性能任务只在基准证明存在回退或 Instruments 指出明确热点时写代码。

### D：发布物

| 编号 | 工作 | 验收 |
| --- | --- | --- |
| D1 | 用户文档 | 四语言手册、网页版手册、双语 README 与 1.0.0 实际界面一致；免费版限制和 App Store 链接明确 |
| D2 | 商店素材 | 使用 RC 界面制作四语言截图；ASC validate 通过；元数据以“稳定正式版 1.0”为叙事 |
| D3 | RC | 内部 TestFlight 完成一次完整主流程；RC 期只接受 P0/P1 修复 |
| D4 | 正式发布 | App Store 提审采用 `AFTER_APPROVAL`；GitHub v1.0.0 workflow 成功；下载资产完成脱沙箱签名、公证与 Gatekeeper 验证 |

## 四、明确不做

- 不为统一外观替换所有 padding、字号、圆角和 `controlSize`。
- 不承诺“每个错误都有重试按钮”；无法在原地恢复时，清楚说明原因即可。
- 不提交大体积真实视频、FIT 或性能样本；基准只提交配置与结果，素材保留在忽略目录。
- 不要求不同编码器或不同硬件生成的文件字节级、逐帧压缩结果一致。
- 不以测试数量、文档页数或代码改动量作为完成度指标。

## 五、优先级与放行规则

| 级别 | 定义 | 1.0.0 规则 |
| --- | --- | --- |
| P0 | 数据丢失、崩溃、隐私/授权失效、透明 Alpha 或导出错误 | 必须清零 |
| P1 | 主路径阻断、明显状态错乱、严重性能回退、四语言主界面不可用 | 必须清零 |
| P2 | 不阻断任务的视觉、文案与便利性问题 | 有余量再做，未做项记录到 1.0.1 |

发现问题后直接附复现路径、证据、级别和最小验证；无需先建立独立审计项目。分级有争议时由用户裁定。
