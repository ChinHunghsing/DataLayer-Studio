# DataLayer Studio 使用说明（简体中文）

最后更新：2026-07-06

本文面向第一次使用 DataLayer Studio 的用户，按从准备素材到导出成片的完整流程说明。照着做一遍后，你应该能独立完成：导入视频和运动文件、校准时间、排布数据层、导出透明浮层或合成视频。

## 1. DataLayer Studio 是做什么的

DataLayer Studio 用来把跑步运动数据做成视频数据层。你可以把手表或运动平台导出的 `.fit` / `.gpx` 文件，与一段跑步视频同步，然后把配速、速度、心率、步频、功率、路线、距离进度、天气、时间日期等信息叠加到画面上。

它支持两种输出：

- **透明浮层视频**：导出带 Alpha 通道的 `.mov`，放到 Final Cut Pro、DaVinci Resolve、Premiere 等剪辑软件的上层轨道。
- **合成视频**：直接导出已经叠加数据层的视频，适合快速分享。

它也支持两种使用方式：

- **图形界面**：适合第一次使用、手动调布局、预览效果。
- **命令行工具**：适合批量制作，复用同一个布局预设。

## 2. 使用前准备

### 2.1 系统要求

- 需要 Apple Silicon 芯片的 Mac。
- 需要 macOS 13.0 Ventura 或更新版本。
- App Store 版本需要有效购买记录。若提示收据不可验证，可先尝试“恢复购买”。

### 2.2 需要准备的文件

最常见的完整流程需要两个文件：

- **视频文件**：你拍摄的跑步视频。横屏、竖屏都可以。
- **运动文件**：`.fit` 或 `.gpx`。

只做透明数据层时，视频不是绝对必须；但如果你想在软件里对着画面排版，或者要直接导出合成视频，就需要源视频。

### 2.3 FIT 和 GPX 的区别

优先使用 `.fit`。FIT 通常包含更完整的跑步指标，例如心率、步频、功率、温度、跑姿数据等。

`.gpx` 通常只包含轨迹点和时间，常见可用数据是路线、距离、速度、配速和时间。它不一定包含心率、功率、步频等字段。缺少字段时，对应数据层可能无法添加，或者显示为 `--`。

### 2.4 视频素材建议

- 尽量先使用原始视频，不要先裁到奇怪比例。
- 如果后期要发短视频，可以在 DataLayer Studio 里先按竖屏预设导出，或导出透明浮层后进剪辑软件再裁切。
- 如果视频从开跑前就开始录，后续同步会更容易。
- 如果视频是中途开始录，也可以同步，只是需要找到视频画面中某个能和运动时间对应的瞬间。

### 2.5 运动文件建议

- 从手表、码表或运动平台导出原始 `.fit`，不要只导出截图或网页分享链接。
- 运动文件最好和视频来自同一次活动。
- 如果活动中暂停过，DataLayer Studio 会尽量按运动文件里的时间数据处理；但不同设备导出的文件规则可能不同，最终以预览和导出结果为准。

## 3. 界面结构

打开 App 后，主界面可以理解成四个区域：

- **左侧素材与画布面板**：选择视频、选择运动文件、设置网格、保存/载入布局预设。
- **中间预览画布**：播放视频、查看数据层、拖动和缩放浮层。
- **底部工作区**：同步、裁剪、输出三个主要步骤。
- **右侧检查器**：选中某个数据层后，调整它的位置、文字、样式、字体和数据参数。

建议第一次使用时按这个顺序操作：

1. 选择视频。
2. 选择 FIT/GPX。
3. 在“同步”里对齐视频和运动时间。
4. 在画布上排布数据层。
5. 在“裁剪”里确定导出范围。
6. 在“输出”里选择导出方式并导出。

## 4. 第一次完整制作流程

### 4.1 导入视频

在左侧“素材”区域点击“视频”，选择源视频文件。也可以使用快捷键 `⌘O`。

导入后：

- 中间会显示视频预览。
- 输出设置里可以选择“源视频分辨率”和“源视频帧率”。
- 后续可以导出“合成视频”。

如果视频加载失败，左侧会显示错误和“重试”。常见原因包括文件损坏、系统无法读取该编码、文件路径不可访问。

### 4.2 导入运动文件

在左侧“素材”区域点击“运动文件”，选择 `.fit` 或 `.gpx`。也可以使用快捷键 `⌘F`。

导入后：

- 数据层预览才会真正可用。
- 软件会读取运动时间、距离、速度/配速、轨迹和其他可用指标。
- 如果文件包含 GPS 和日期时间，时间日期、路线、天气等组件更容易正常工作。

如果运动文件加载失败：

- 先确认文件确实是 `.fit` 或 `.gpx`。
- 如果 FIT 来自第三方平台并提示 CRC 问题，命令行有 `--skip-fit-crc` 可用于尝试解析。
- 如果 GPX 没有可用轨迹点，路线和距离相关数据无法生成。

### 4.3 校准视频和运动时间

进入底部工作区的“同步”。

同步的目的：告诉软件“视频里的某一帧，对应运动文件里的哪一个运动时间”。

#### 最推荐：当前画面就是运动开始

适合视频里能看到开跑、按下手表、起跑线、明显开始跑的画面。

操作：

1. 播放或拖动时间轴，找到运动开始那一帧。
2. 点击“当前画面就是运动开始”。
3. 软件会把这个视频时间设为运动 `00:00`。
4. 播放几秒，检查配速、距离、路线进度是否合理。

快捷键：`⌘⇧S`。

#### 使用匹配点

适合视频不一定从运动开始拍，但你能找到一个明确瞬间。例如：

- 跑过某个路口。
- 经过一个桥、门、补给点。
- 视频里看到手表上的时间。
- 你知道视频第 12 秒对应运动第 3 分 20 秒。

操作：

1. 在预览里定位视频时间。
2. 在“视频”输入该视频时间。
3. 在“运动”输入同一瞬间对应的运动时间。
4. 查看“当前预览”映射提示是否合理。

例子：视频 `00:12.000` 处对应运动 `03:20.000`，就在视频填 12 秒，在运动填 3 分 20 秒。

#### 视频开头模式的理解

如果录像开始时，运动已经开始了一段时间，就让视频 `00:00` 对应某个运动用时。

例子：

- 你跑了 5 分钟后才开始录视频。
- 视频开头对应运动第 5 分钟。
- 那么视频 `00:00` 对应运动 `05:00`。

#### 手动偏移的理解

手动偏移适合熟悉时间线的人。正数表示运动在视频中稍后开始；负数表示视频从运动中途开始。

如果第一次使用，不建议直接用手动偏移。优先用“当前画面就是运动开始”或匹配点。

### 4.4 检查同步是否准确

同步完成后，播放视频并观察：

- 距离是否随着画面中的跑步进展增加。
- 路线上的当前位置是否大致符合画面位置。
- 配速变化是否和画面中的快慢变化接近。
- 心率、步频等是否在合理时间出现。

如果感觉数据提前了：

- 说明运动时间相对视频跑得太快。
- 重新找同步点，把运动时间设得稍晚一些，或把视频同步点往后找。

如果感觉数据滞后了：

- 说明运动时间相对视频跑得太慢。
- 重新找同步点，把运动时间设得稍早一些，或把视频同步点往前找。

如果视频有一段开跑前准备画面：

- 同步点可以放在真正运动开始那一帧。
- 运动开始前的画面会保持第一个运动样本，不会虚构负数运动数据。

如果视频比运动文件更长：

- 超出运动数据结尾后，数据层会保持最后一个样本。
- 建议用“裁剪”限制导出范围，避免片尾长时间停在最后数据。

## 5. 数据层和组件

### 5.1 默认数据层

默认布局会包含常用数据层。你可以直接拖动它们，也可以删除、隐藏、复制、添加更多组件。

常见推荐组合：

- 社交短视频：路线、距离、配速、心率。
- 比赛回顾：路线、距离进度、配速、心率、时间。
- 训练复盘：配速、心率、步频、功率、垂直振幅、触地时间。
- 画面干净优先：只保留路线和一两个关键指标。

### 5.2 可添加的组件

右侧检查器顶部有“添加”菜单。可添加组件包括：

- 速度
- 配速
- 心率
- 步频
- 热量
- 累计爬升
- 步幅
- 功率
- 垂直振幅
- 触地时间
- 触地时间占比
- 触地平衡
- 垂直比
- 呼吸频率
- 步速损失百分比
- 形态功率
- 空气功率
- 腿部弹簧刚度
- 天气
- 距离数值
- GPS 轨迹
- 距离进度
- 时间和日期

如果某个组件在“添加”菜单里不可用，通常是因为当前运动文件没有对应数据。例如 GPX 往往没有心率、功率和跑姿数据。

### 5.3 组件缺数据时怎么办

组件显示 `--` 或无法添加时，先判断数据来源：

- 心率需要运动文件里有 heart rate。
- 步频需要 cadence。
- 功率需要 power。
- 路线需要 GPS 经纬度。
- 天气需要运动文件里有时间和 GPS 位置，并且配置了 OpenWeather。
- 垂直振幅、触地时间、触地平衡、垂直比等通常依赖支持跑姿数据的设备。
- 形态功率、空气功率、腿部弹簧刚度、步速损失等可能来自特定设备或 developer fields，不是每个 FIT 都有。

如果你只是想做一条好看的分享视频，不必强行显示所有指标。缺数据时优先保留路线、距离、配速、心率这类更容易理解的信息。

## 6. 在画布上排布数据层

### 6.1 选择组件

在中间预览画布上点击一个可见数据层，它会变成选中状态，右侧检查器显示该组件的设置。

如果没有选中任何组件，右侧会提示“选择或添加浮层”。

### 6.2 移动组件

直接拖动组件即可移动位置。建议：

- 不要遮住跑者、路口、字幕、logo 等重要画面。
- 竖屏视频尽量把数据放在上方或下方，避开主体人物。
- 多个组件最好沿同一边缘对齐。

也可以使用方向键微调选中元素。

### 6.3 缩放组件

选中组件后，在右侧“布局”里调整“大小”。范围大致是 45% 到 180%。

距离进度条还支持“长度”调整，适合横跨画面顶部或底部。

### 6.4 使用网格和吸附

左侧“画布”区域可以开启：

- **显示网格**：在预览上显示辅助网格。
- **拖动时吸附**：移动组件时吸附到网格。
- **列数 / 行数**：调整网格密度。

建议第一次排版时开启网格，组件位置确定后再关闭网格看最终效果。

### 6.5 隐藏、复制、删除和层级

选中组件后，右侧顶部有几个常用操作：

- 眼睛图标：显示或隐藏该组件。隐藏后不会出现在预览和导出里。
- 复制：复制当前组件和它的样式。
- 上移一层 / 下移一层：调整遮挡关系。
- 删除：从当前布局中移除组件。

快捷键：

- 上移一层：`⌘⌥↑`
- 下移一层：`⌘⌥↓`

### 6.6 撤销和重做

移动、编辑、添加、删除、复制、图层重排、套用预设都支持系统撤销/重做。可以使用 macOS 常规快捷键：

- 撤销：`⌘Z`
- 重做：`⇧⌘Z`

## 7. 右侧检查器详解

右侧检查器按五个分区组织：布局、内容、外观、字体、数据。

### 7.1 布局

用于控制组件在画布中的位置和大小：

- **X / Y**：组件在画布中的位置。
- **大小**：整体缩放。
- **长度**：部分组件可用，例如距离进度条。

如果要精确对齐，建议配合网格和吸附使用。

### 7.2 内容

用于控制组件显示哪些文字：

- **标签**：例如 PACE、HR、DISTANCE。
- **标签文字**：自定义标签。
- **单位**：例如 `/KM`、`BPM`、`W`。
- **单位文字**：自定义单位。
- **图标**：显示或隐藏图标。
- **图标文字**：自定义图标文字。
- **天气图标**：天气组件可以选择自动、晴、多云、雨、雪、雷暴、雾、风。

如果画面空间小，可以关闭标签或图标，只保留数值。

### 7.3 外观

用于控制组件背景和线条：

- **面板**：开启/关闭组件背景。
- **面板边框**：开启/关闭边框。
- **面板透明度**：让背景更明显或更轻。
- **线宽**：速度仪表、GPS 轨迹、距离进度等线条组件可调。
- **轨道颜色**：调整进度轨道或仪表背景线。
- **进度条颜色**：距离进度条可单独调整。
- **侧边距 / 滑块大小 / 数值间距**：用于细调距离进度条。
- **刻度线 / 刻度数量**：用于速度仪表和距离进度条等支持刻度的组件。

建议：

- 明亮视频上增加面板透明度或边框。
- 夜景视频上可以降低面板透明度，让数据层更轻。
- 短视频里线条不要太细，否则手机上看不清。

### 7.4 字体

用于控制标签、数值、单位、图标的字体、颜色和字号。

可调内容因组件不同而不同：

- 普通指标块：标签、数值、单位、图标。
- 距离进度条：起始距离、实时距离、最终距离、图标。
- 时间日期：时间和日期的显示。

建议：

- 数值字号最大，标签和单位小一些。
- 同一画面里不要混用太多字体。
- 如果要做社交短视频，优先保证手机屏幕上能看清数值。

### 7.5 数据

用于控制数据本身的显示方式：

- 支持小数位的组件可以设置 0 到 3 位小数。
- 速度仪表可以设置仪表最小值和最大值。
- 速度仪表可以开启/关闭刻度。
- 天气组件可以填写 OpenWeather API key 并刷新天气。

不是所有组件都有“数据”分区。如果某个组件没有数据专属设置，检查器会提示“没有数据设置”。

## 8. 天气数据

天气组件可以显示温度、湿度和天气图标。

### 8.1 使用条件

需要同时满足：

- 当前运动文件有可用时间。
- 当前运动文件有 GPS 位置。
- 你填写了 OpenWeather API key。
- 这个 key 已开通 OpenWeather One Call 4.0 权限。

### 8.2 配置方式

1. 添加或选中“天气”组件。
2. 在右侧“数据”分区找到“天气数据”。
3. 点击 API key 页面链接，登录 OpenWeather。
4. 复制已开通 One Call 4.0 的 key。
5. 粘贴到 DataLayer Studio 的 OpenWeather API key 输入框。
6. 点击“刷新天气”。

Key 只保存在本机。每个运动文件的天气结果会本地缓存，避免重复消耗 API 次数。

### 8.3 天气不可用时

常见原因：

- 没有填写 key。
- key 没有 One Call 4.0 权限。
- 运动文件没有 GPS。
- 运动文件没有时间。
- OpenWeather 请求失败或当前网络不可用。

不需要天气时，可以隐藏或删除天气组件，不影响其他数据层。

## 9. 裁剪

底部工作区的“裁剪”包含两个概念：运动数据范围和导出范围。

### 9.1 运动数据范围

“运动数据范围”只影响浮层数据如何归零显示。同步仍然使用裁剪前的原始运动时间轴。

适合场景：

- 一次活动里只想展示其中一段。
- 想让这段开始时距离显示为 0。
- 想把比赛中的某一段单独做成视频。

操作：

1. 把预览播放头移动到要作为数据开始的位置。
2. 点击“当前为数据开始”。
3. 把播放头移动到数据结束位置。
4. 点击“当前为数据结束”。
5. 需要恢复时点击“完整运动”。

### 9.2 导出范围

“导出范围”决定最终输出视频的开始、结束和时长。

适合场景：

- 只导出视频中间一段。
- 去掉开头准备和结尾无关画面。
- 避免运动结束后数据停在最后一帧太久。

操作：

1. 把预览播放头移到导出开始位置。
2. 点击“当前为开始”。
3. 把预览播放头移到导出结束位置。
4. 点击“当前为结束”。
5. 需要恢复整段时点击“整段”。

导出时长必须至少 0.1 秒，最长不超过 24 小时。

## 10. 输出设置

进入底部工作区的“输出”。

### 10.1 分辨率

可选：

- 源视频分辨率：有视频时可用。
- 4K UHD 3840×2160
- QHD 2560×1440
- FHD 1920×1080
- HD 1280×720
- 竖屏 2160×3840
- 竖屏 1080×1920
- 竖屏 720×1280
- 自定义

自定义宽高要求：

- 最小 2 px。
- 最大 16384 px。
- 必须是偶数。

如果没有源视频，默认是 `1920×1080`。

### 10.2 帧率

可选：

- 源视频帧率：有视频时可用。
- 23.976 fps
- 24 fps
- 25 fps
- 29.97 fps
- 30 fps
- 50 fps
- 59.94 fps
- 60 fps
- 自定义

自定义帧率要求：

- 最小 1 fps。
- 最大 240 fps。

如果没有源视频，默认是 `30 fps`。

### 10.3 码率

码率单位是 `kbps`。默认是 `12000 kbps`。

一般建议：

- 1080p：8000 到 16000 kbps。
- 4K：30000 到 80000 kbps。
- 透明浮层：如果只是简单线条和文字，默认值通常够用。

有效范围是 1 到 1000000 kbps。码率过大可能被系统或 App 拦截。

### 10.4 距离单位

可选：

- 米 `(m)`
- 公里 `(km)`

这会影响距离标签和相关显示。默认是公里。

### 10.5 编码

透明浮层可选：

- **带透明通道的 HEVC/H.265**：默认，文件通常较小。
- **Apple ProRes 4444**：适合作为高质量中间文件，文件更大。

合成视频可选：

- **HEVC/H.265**：默认，压缩效率高。
- **H.264**：兼容性更广，文件可能更大。

注意：透明浮层必须使用支持 Alpha 的编码。合成视频不需要 Alpha 编码。

### 10.6 导出目标

可以提前选择“另存为”，也可以保持“导出时询问”。

默认文件名规则大致是：

- 透明浮层：`原文件名_overlay.mov`
- 合成视频：`原文件名_with_overlay.mov`

如果目标文件已存在，导出时会提示是否覆盖。

## 11. 透明浮层导出

透明浮层适合后期剪辑软件。

操作：

1. 在“输出”中检查分辨率、帧率、码率、编码和目标。
2. 点击“导出浮层”。
3. 等待进度完成。
4. 完成后可以在访达中显示或打开文件。
5. 在剪辑软件中把导出的 `.mov` 放到原视频上方轨道。

如果普通播放器打开后看到黑底，不一定是导出失败。很多播放器不会正确显示 Alpha 通道。请放进剪辑软件上层轨道检查。

适合使用透明浮层的情况：

- 你还要在剪辑软件里调色。
- 你还要裁切、变速、加字幕或做多机位。
- 你想保留原视频和数据层分离，方便修改。

## 12. 合成视频导出

合成视频会把源视频、音频和数据层一起输出。

操作：

1. 必须先选择源视频。
2. 必须先选择 FIT/GPX。
3. 在“输出”里检查分辨率、帧率、码率、编码和目标。
4. 点击“导出视频”。
5. 等待导出完成。

适合使用合成视频的情况：

- 不想再进剪辑软件。
- 只是快速生成一条可分享视频。
- 画面、声音和数据层已经在 DataLayer Studio 里确认无误。

如果没有选择源视频，“导出视频”不可用；这时只能导出透明浮层。

## 13. 导出进度、取消和结果

导出时会显示：

- 进度。
- 预计剩余时间。
- 取消按钮。

取消导出：

- 可以点击取消。
- 也可以使用 `⌘.`。
- 取消前会二次确认。
- 未完成的输出会被移除。

导出完成后：

- 会显示导出的文件名和用时。
- 可以点击“在访达中显示”。
- 可以点击“打开”。
- 系统通知也会提示导出完成。

导出失败时：

- 结果弹窗会显示错误。
- 调试控制台里可以查看导出日志。
- 先检查输出路径、磁盘空间、编码选择、分辨率和码率。

## 14. 布局预设

布局预设可以保存一套数据层排布和样式，之后复用到其他视频。

### 14.1 保存预设

1. 排好当前画布。
2. 在左侧“画布”区域找到“预设”。
3. 输入预设名称。
4. 点击保存按钮。

如果同名预设已存在，软件会更新该预设。

### 14.2 载入预设

在预设列表中点击载入按钮。载入前会二次确认，因为它会替换当前画布布局。未保存的当前布局会丢失。

### 14.3 设为默认

点击星标按钮可把某个预设设为默认。以后打开 App 时会优先使用这个布局。

### 14.4 删除预设

点击删除按钮并确认。删除预设不会改变当前画布上的布局，只会移除保存的预设。

### 14.5 导入和导出预设

可以把预设导出为 JSON 文件，用于备份或迁移到另一台 Mac。也可以导入别人提供的预设 JSON。

导入时会自动处理重复 ID 和重复名称，尽量避免覆盖现有预设。

### 14.6 iCloud 同步

左侧会显示预设同步状态：

- 仅本地
- 已就绪
- 已请求上传
- 收到 iCloud 更新

iCloud 状态只影响预设同步，不影响当前项目导出。

## 18. 命令行使用

命令行工具适合批量导出或自动化流程。它和图形界面使用同一套核心渲染逻辑。

### 18.1 最小示例

```bash
swift run overlay \
  --video /path/to/run-video.mov \
  --fit /path/to/activity.fit \
  --output /path/to/overlay.mov
```

默认会导出透明浮层。

### 18.2 只导出透明浮层

```bash
swift run overlay \
  --video /path/to/run-video.mov \
  --fit /path/to/activity.fit \
  --output /path/to/overlay.mov \
  --export-mode overlay
```

也可以不传 `--video`，这时默认输出 `1920×1080`、`30 fps` 的透明浮层：

```bash
swift run overlay \
  --fit /path/to/activity.fit \
  --output /path/to/overlay.mov \
  --width 1920 \
  --height 1080 \
  --fps 30
```

### 18.3 导出合成视频

合成视频必须提供 `--video`。

```bash
swift run overlay \
  --video /path/to/run-video.mov \
  --fit /path/to/activity.fit \
  --output /path/to/final.mov \
  --export-mode video
```

### 18.4 指定同步方式

录像比运动早开始 12 秒：

```bash
swift run overlay \
  --video run.mov \
  --fit activity.fit \
  --output overlay.mov \
  --offset 12
```

视频从运动第 500 秒开始：

```bash
swift run overlay \
  --video run.mov \
  --fit activity.fit \
  --output overlay.mov \
  --fit-start 500
```

任意匹配点：视频第 3.2 秒对应运动第 2475 秒：

```bash
swift run overlay \
  --video run.mov \
  --fit activity.fit \
  --output overlay.mov \
  --sync-video 3.2 \
  --sync-fit 2475
```

注意：

- `--offset` 不能和 `--fit-start`、`--sync-video`、`--sync-fit` 混用。
- `--fit-start` 不能和 `--sync-video`、`--sync-fit` 混用。
- 使用匹配点时，`--sync-video` 和 `--sync-fit` 必须成对出现。

### 18.5 指定输出参数

```bash
swift run overlay \
  --video run.mov \
  --fit activity.fit \
  --output overlay.mov \
  --width 1920 \
  --height 1080 \
  --fps 30 \
  --bitrate 12000 \
  --codec hevc-alpha \
  --distance-unit km
```

参数说明：

- `--width`：输出宽度，2 到 16384，必须是偶数。
- `--height`：输出高度，2 到 16384，必须是偶数。
- `--fps`：输出帧率，至少 1。
- `--bitrate`：平均码率，单位 kbps。
- `--bitrate-bps`：旧版 bps 写法。
- `--distance-unit`：`km` 或 `m`。

编码：

- 透明浮层：`hevc-alpha`、`prores-4444`。
- 合成视频：`hevc`、`h264`。

### 18.6 使用布局预设

使用图形界面里保存过的预设：

```bash
swift run overlay \
  --video run.mov \
  --fit activity.fit \
  --output overlay.mov \
  --layout-preset "Race Layout"
```

也可以使用从图形界面导出的 JSON：

```bash
swift run overlay \
  --video run.mov \
  --fit activity.fit \
  --output overlay.mov \
  --layout-preset /path/to/presets.json
```

查找逻辑：

- 如果传入的是现有 JSON 文件路径，就读取文件里的预设。
- 如果传入的是名称或 ID，就从图形界面的本地预设里查找。
- 如果 JSON 里有默认预设，优先使用默认预设；否则使用第一个可用预设。

### 18.7 裁剪运动数据

```bash
swift run overlay \
  --video run.mov \
  --fit activity.fit \
  --output overlay.mov \
  --activity-trim-start 300 \
  --activity-trim-end 900
```

这表示只使用原始运动时间第 300 秒到第 900 秒的数据，并把显示重新归零。

### 18.8 只检查元数据不导出

```bash
swift run overlay \
  --fit activity.fit \
  --output inspect.mov \
  --inspect
```

`--inspect` 会解析视频和运动数据，打印元数据，不渲染输出。

### 18.9 FIT CRC 异常时尝试解析

```bash
swift run overlay \
  --fit activity.fit \
  --output overlay.mov \
  --skip-fit-crc
```

这个参数只对 FIT 有意义，GPX 会忽略。

## 19. 常见工作流

### 19.1 做一条可直接分享的视频

1. 导入视频。
2. 导入 FIT。
3. 设置运动开始。
4. 保留路线、距离、配速、心率。
5. 裁掉开头和结尾无关片段。
6. 输出选择合成视频。
7. 编码选 HEVC/H.265。
8. 导出。

### 19.2 给剪辑软件做透明数据层

1. 导入视频和 FIT。
2. 同步到准确时间。
3. 排好数据层，不要遮住主体。
4. 输出选择透明浮层。
5. 编码选带透明通道的 HEVC/H.265 或 ProRes 4444。
6. 导出 `.mov`。
7. 在剪辑软件中把 `.mov` 放到原视频上方轨道。

### 19.3 做竖屏短视频

1. 导入横屏或竖屏原视频。
2. 同步运动数据。
3. 输出分辨率选择竖屏 1080×1920 或竖屏 2160×3840。
4. 把数据层集中到上方、下方或一侧。
5. 手机预览时确保字足够大。
6. 导出合成视频，或导出透明浮层后进剪辑软件裁切。

### 19.4 一次活动只展示中间一段

1. 导入视频和运动文件。
2. 先完成同步。
3. 在“裁剪”里设置运动数据范围，让该段距离归零。
4. 设置导出范围，只导出对应片段。
5. 导出。

### 19.5 多个视频复用同一套样式

1. 在第一个视频里排好布局。
2. 保存为布局预设。
3. 后续视频导入后载入这个预设。
4. 每个视频只微调同步和位置。
5. 如果数量多，用 CLI 的 `--layout-preset` 批量导出。

## 20. 常见问题和排障

### 20.1 没有数据层预览

检查：

- 是否已经选择 FIT/GPX。
- 运动文件是否加载成功。
- 预览是否有警告。
- 是否把所有组件隐藏了。
- 当前时间是否在运动数据范围外。

### 20.2 组件无法添加

通常是当前运动文件没有对应字段。例如：

- GPX 没有心率，所以心率不可用。
- 没有 GPS，所以路线不可用。
- 没有功率，所以功率不可用。
- 没有跑姿数据，所以触地时间、垂直振幅等不可用。

解决方式：

- 换用原始 FIT 文件。
- 从运动平台重新导出更完整的数据。
- 删除缺数据的组件，换成当前文件可用的指标。

### 20.3 数据和画面对不上

解决顺序：

1. 重新找到更清楚的同步点。
2. 用“当前画面就是运动开始”重新设置。
3. 如果视频从中途开始，改用匹配点。
4. 播放 10 到 20 秒确认路线、距离和配速是否合理。

### 20.4 视频能播放，但导出按钮不可用

看导出按钮附近的提示。常见原因：

- 没有选择 FIT/GPX。
- 导出合成视频但没有选择源视频。
- 编码和导出类型不匹配。
- 宽高不是偶数。
- 宽高、帧率或码率超出范围。
- 导出目标文件夹不可写。
- 导出时长太短或太长。

### 20.5 透明视频在播放器里是黑底

很多普通播放器不会正确显示 Alpha 通道。这通常不是导出失败。

检查方式：

- 把透明 `.mov` 放到剪辑软件上层轨道。
- 下方放原视频或任意背景。
- 如果能看到数据层叠加，说明 Alpha 正常。

### 20.6 导出很慢

可能原因：

- 分辨率太高。
- 帧率太高。
- 码率太高。
- ProRes 4444 文件更大。
- 视频时长太长。

优化方式：

- 先用 1080p 和 30 fps 测试。
- 缩短导出范围。
- 只导出透明浮层，再进剪辑软件合成。
- 避免不必要的 4K 或 60 fps。

### 20.7 导出失败

先检查：

- 目标磁盘空间是否足够。
- 输出文件是否被其他软件占用。
- 目标文件夹是否可写。
- 编码是否和导出类型匹配。
- 分辨率宽高是否为偶数。
- 码率是否过大。

再打开调试控制台查看导出日志。

### 20.8 天气刷新失败

检查：

- OpenWeather key 是否填写。
- key 是否开通 One Call 4.0。
- 网络是否可用。
- 运动文件是否有 GPS 和时间。
- 当前 API 额度是否耗尽。

不影响导出时，可以隐藏天气组件。

### 20.9 画面太挤

建议：

- 只保留 3 到 5 个核心数据。
- 关闭不必要的标签、单位或图标。
- 把数据层分组放在同一边。
- 使用路线和距离进度替代大量数字。
- 竖屏视频不要把数据层放在人物脸部和身体中心。

### 20.10 字太小

解决：

- 选中组件。
- 到“字体”分区增大数值字号。
- 必要时增大整体“大小”。
- 移动组件，给文字留空间。
- 手机观看的视频优先让数值清楚，标签可以缩小或隐藏。

### 20.11 路线看起来不完整

可能原因：

- 运动文件本身 GPS 断点。
- 运动数据范围被裁掉。
- 当前时间还没跑到对应位置。
- 路线组件太小或线宽太细。

可以尝试：

- 取消运动数据范围裁剪。
- 放大路线组件。
- 增加线宽。
- 换用更完整的 FIT/GPX。

### 20.12 FIT/GPX-only 是什么意思

如果你只选择运动文件，不选择视频：

- 可以预览和导出运动数据的透明浮层。
- 不需要做视频同步。
- 默认输出尺寸是 `1920×1080`，帧率是 `30 fps`，可以手动修改。
- 不能导出合成视频，因为没有源视频可合成。

适合先批量生成数据层，再到剪辑软件里统一叠加。

### 20.13 预设载入后当前布局不见了

这是预期行为。载入预设会替换当前画布布局。

建议：

- 载入前先保存当前布局为预设。
- 或使用撤销恢复。

### 20.14 App 提示需要购买记录

App Store 版本会验证购买记录。

可尝试：

- 点击“恢复购买”。
- 确认使用的是购买 DataLayer Studio 的 Apple ID。
- 从 App Store 重新安装。
- 确认系统能访问 App Store 服务。

## 21. 隐私和数据

DataLayer Studio 的核心处理在本机完成。视频、FIT/GPX 和导出文件不会因为基本渲染流程被上传。

需要注意：

- 使用天气功能时，会向 OpenWeather 请求天气数据，请求依赖活动时间和 GPS 位置。
- OpenWeather API key 保存在本机。
- 每个运动文件的天气结果会本地缓存。
- 反馈问题时不要公开包含 GPS 轨迹、姓名、账号 ID、设备 ID、本地路径的文件或日志。

## 22. 新手建议

第一次使用时，不要一开始就追求复杂排版。推荐这样做：

1. 用原始视频和原始 FIT。
2. 只保留路线、距离、配速、心率。
3. 先用“当前画面就是运动开始”完成同步。
4. 先导出 10 秒小片段检查。
5. 确认同步和字体大小后，再导出完整视频。
6. 保存布局预设，下次复用。

如果最终要进剪辑软件，优先导出透明浮层；如果只是快速分享，直接导出合成视频。
