## 这份文档的用途

这份文档是下一轮时间线工作的当前事实基线。`docs/timeline-phase4-plan.md` 记录了阶段 4 的原始拆分，但其中“工程保存/打开仍未完成”等状态已经过期；判断真实能力和下一步优先级时，以本文和当前代码为准。

目标仍然是把 DataLayer Studio 从“单视频 + 单运动文件”改造成轻量时间线：

- 一个工程包含多个视频和多个 FIT/GPX。
- 视频片段可分散放在时间线上，开头、片段之间和结尾都允许没有视频。
- 运动数据作为浮层片段放在 overlay track，可移动、裁剪、叠加。
- 预览和导出读取同一个 `TimelineProject`。
- 保持透明 HEVC Alpha / ProRes 4444 的质量和逐帧流式写出，不重新引入透明区域发灰或整段缓存导致的内存问题。

这不是完整 NLE。当前范围不包含画中画、多机位或转场；多视频轨重叠采用标准的全画面“上层视频覆盖下层视频”语义。

## 当前真实架构与语义

### 核心模型

- `Sources/OverlayCore/Timeline/TimelineModel.swift`
- `TimelineProject.assets` 保存媒体资产；`tracks` 按自底向上的合成顺序排列。
- `TimelineTrack.Kind` 目前有 `video` 和 `overlay`。
- `TimelineTrack.clip(atTimelineTime:)` 在同轨片段重叠时返回数组中最后一个片段。
- `TimelineClip` 的区间是左闭右开：`timelineStart <= t < timelineEnd`。
- 片段源时间映射为 `sourceIn + (t - timelineStart)`。
- 反向映射为 `timelineStart + (sourceTime - sourceIn)`；`TimelineProject.alignMatchPoint` 用它对齐两个素材源时间，不裁掉任一素材的开头。
- `TimelineProject.duration` 是所有轨道最远的片段结束时间，不只看视频轨。
- `TimelineProject.sourceMatchPoint` 可选保存当前主视频与主运动素材的源时间对应关系；它和片段的 `timelineStart` 独立，旧 JSON 缺字段仍可解码。
- 单源迁移使用稳定的 `single.video.*` / `single.overlay.*` ID；这是 SwiftUI 拖拽不中断的必要条件，不要改回随机 ID。
- 单源迁移始终保留视频和运动素材全长、`sourceIn == 0`；若相对同步会产生负起点，就把这对片段整体右移，而不是裁掉源素材开头。

### App 状态

- 实际文件是 `Sources/OverlayStudio/Stores/StudioModel.swift`，不是旧文档写的 `Models/StudioModel.swift`。
- `StudioModel.timeline` 是预览和导出的当前时间线状态。
- 初始单源工作流仍兼容旧工程的源匹配点；第一次移动、手动输入起点或裁剪任意 `single.*` 片段，或把池中素材加入时间线后进入自定义时间线模式。
- 旧工程的“视频源时间 ↔ 运动源时间”匹配点继续解码和保存，但 App 不再提供独立同步面板；当前对齐方式是直接移动片段或编辑片段的 `timelineStart`。
- 自定义模式下，输出宽高、帧率、距离单位会更新工程设置，不会重建并覆盖多片段结构。
- 活动数据按 `assetID` 缓存在 `activitySeriesByAssetID`，预览和导出据此为每个浮层片段找到各自的 telemetry。
- `hasUnsavedTimelineChanges` 通过当前 `timeline` 与最近保存/打开的 clean snapshot 自动比较；窗口标题使用 macOS document-edited 状态显示未保存标记。
- 自定义时间线切换媒体池活动源、删除被片段引用的素材、打开其他工程和关闭含未保存修改的窗口都会先显示四语言确认，不再静默覆盖。

### UI 已有能力

- 视频/FIT/GPX Finder 导入支持多选；第一个仍成为活动源，全部选中素材都会自动加入时间线。即使异步元数据加载/运动数据解析的完成顺序不同，落位仍严格保持 Finder 选择顺序。
- 导入前时间线为空时，首个素材从 0 开始；时间线已有片段时，首个新素材从整个工程末尾开始，其余选中素材依次顺延。
- 媒体池的“加入时间线”按钮：
  - 视频和运动素材都从整个工程末尾追加，而不是使用当前播放头位置。
  - 优先复用第一条未锁定的同类型轨道；只有不存在可用同类型轨道时才创建轨道。
- 媒体池“使用中”按素材是否被任意时间线片段引用判断，不再只标记单一活动源；所有被引用的视频和运动素材都会显示该状态。
- 视频和运动素材都可从媒体池拖到同类型现有轨道，按落点时间加入最近可容纳的空隙。
- 时间线工具栏有“新增视频轨道”入口；新轨按 V2、V3 递增，位于现有视频轨上方、overlay 轨下方。默认“加入时间线”仍复用第一条可用视频轨，只有显式新建并拖放时才使用其他视频轨。
- 时间线显示标尺、视频轨、浮层轨、片段、播放头和导出 in/out 带；轨道总高度超过工作区时可纵向滚动。
- 时间线可用工具栏或触控板横向缩放，缩放及 ↑/↓ 跳转剪辑点后，视口以播放头为焦点；播放和手动擦洗不会强制自动跟随。
- 删除片段后留下的空轨可从轨道头删除，且支持撤销；有片段的轨道不会显示删除入口。
- 视频片段按素材异步抽取并缓存 512 个音频峰值，在片段内部显示音频波形；抽取使用 AVAssetReader 流式解码和 Accelerate 峰值计算，不缓存完整音频。
- 视频和运动数据片段都可自由移动并保留空隙；空隙是合法内容，不会自动 ripple，也不强制任一首片段从 0 开始。
- 同一轨道上的片段不允许重叠：移动、裁剪、检查器编辑和拖放落点都会钳制到最近的可容纳空隙（`TimelineTrack.nonOverlappingStart`/`neighborBounds`）；片段可以精确贴边。旧工程里已有的重叠仍按“最后片段生效”解析。
- 时间线编辑支持撤销/重做（⌘Z/⇧⌘Z，标准编辑菜单）：快照式恢复片段几何、单源迁移标志和选中态；拖动/步进按 0.8 秒窗口合并为一步。片段与轨道编辑、重新链接、确认后的活动源替换和素材移除均可撤销/重做；打开其他工程仍会建立新的撤销边界。
- `single.*` 与池中加入的片段使用同一种移动逻辑：拖动或检查器输入只修改被编辑片段自己的 `timelineStart`。
- 所有未锁定片段都可左右裁剪；左裁同时修改 `timelineStart`、`sourceIn`、`duration`，右裁修改 `duration`，最短 0.1 秒。
- ⌘B 在播放头处分割：播放头位于当前选中片段内部时只分割该片段；没有选中片段时分割播放头下全部未锁定轨道；选中片段不在播放头下时不分割其他轨道。两侧源内容连续，左片保留原 ID 和选中态。⌫ 删除选中片段并保留间隙；⇧⌫ 波纹删除，在所有未锁定轨道上闭合被删时间段，跨段片段自动裁剪或拆分（锁定轨不动）。入口有「时间线」菜单和片段右键菜单，实现在 `Sources/OverlayCore/Timeline/TimelineEditing.swift`。
- 移动和裁剪会吸附到时间线 0 点、播放头及其他片段边缘，阈值为当前显示宽度约 6 px；片段移动同时比较头尾两侧，命中时显示黄色参考线和吸附来源。
- 选中片段后，右侧检查器可用时、分、秒、毫秒手动编辑片段的时间线开始位置；同轨冲突仍自动落到最近可容纳空隙，并支持 Undo/Redo。素材入点和时长保持只读，裁剪继续通过时间线手柄完成。运动片段还可设置单片段距离单位和布局，输出页的米/公里选择与当前选中运动片段同步。
- 导出 in/out 带仍是 `StudioModel` 的会话导出范围，不属于 `TimelineProject` 片段几何。
- 底部工作区只显示时间线，不再有“同步”或“裁剪”标签。片段对齐通过拖动或右侧检查器输入起点完成；片段裁切使用时间线手柄，导出范围使用时间线 in/out 带。

### 预览与导出

- 时间线预览按当前时间选择视频片段，并按 overlay 轨顺序合成浮层；只要相对排布不能由旧的 0 起点播放器等价表示，就自动走时间线预览。
- 预览控制条不再显示旧的“运动开始于”同步状态；播放头时间只表示当前时间线位置。
- `TimelineProject.activeClips(kind:atTimelineTime:)` 是预览和 writer 共用的活动片段解析器；同一轨重叠时统一为数组中最后一个片段生效，多轨仍按自底向上顺序合成。
- 自定义时间线播放通过共享 `AVPlayer` 播放由 `TimelineVideoCompositionBuilder` 组装的 `AVMutableComposition`（视频+音频按片段几何摆放、空隙为空段），播放流畅且有声音；擦洗用 `player.seek`，叠加层单独渲染。时间线编辑按视频几何签名防抖 250ms 重建播放器；无视频片段或素材不可读时回退到浮层时钟 + 逐帧抽图。
- `Sources/OverlayCore/Video/TimelineVideoWriter.swift` 是透明浮层和合成视频的统一入口。
- 单浮层透明导出继续委托原 `TransparentVideoWriter`，保护既有 Alpha 路径。
- 多浮层透明导出逐帧渲染和合成，不缓存整段视频。
- 普通合成视频允许导出范围内没有视频：有数据时透明数据层叠在黑色画布上，无数据时输出纯黑帧；只有浮层导出始终保持 Alpha 透明，空白帧也是全透明。
- 视频片段可分散排列；writer 按样本时间戳流式取帧，空隙写黑帧，视频音频保持在对应片段区间，空隙静音。
- 多片段合成导出通过 `AVAssetReaderVideoCompositionOutput` 先规范化剪辑点处的编码、尺寸和帧率变化，避免单一 `TrackOutput` 在读完后以 `Cannot Decode` 失败；尾部视频空隙仍由 writer 补黑帧。
- 多条视频轨允许时间重叠；轨道按工程数组自底向上堆叠，同一时刻取最后一条已启用视频轨的活动片段。上层片段结束后，下层片段从对应的连续源时间恢复，不会从头重播。
- DataLayer Studio 暂无独立音频轨；重叠区间使用当前可见上层视频的音频，上层结束后恢复下层视频对应源时间的音频，避免上下层声音意外叠加。
- 多视频通过 `AVMutableComposition` 组合；每个可见片段使用独立组合轨和自己的 `preferredTransform`，按输出画布等比居中，横竖屏切换不会继承前一片段方向。
- 启用的 overlay 轨按 `TimelineProject.tracks` 自底向上合成；禁用轨不导出。
- `Sources/OverlayCore/Timeline/TimelineExportValidation.swift` 提供 App、CLI 和 writer 共用的导出预检及可见视频片段解析；视频空隙、没有视频和跨视频轨重叠都合法，源范围越界、缺少 asset/telemetry 仍会在编码前返回明确错误。

### 工程保存/打开与 CLI

- App 菜单已有“打开时间线工程”和“保存时间线工程”；保存是每次弹出面板的 Save As 行为。
- 工程格式是直接编码的 `TimelineProject` JSON，不是工程包，也没有独立 schema/version 字段。
- `MediaAsset.bookmarkData` 保存 security-scoped bookmark；旧 JSON 缺该可选字段仍可解码。
- 打开工程时会先应用 JSON，再异步加载各媒体资产。
- 当前 JSON 保存：素材、轨道、片段、输出宽高/帧率、工程距离单位、片段布局/单位，以及可选的主视频/运动源时间匹配点。

- `TimelineModelTests` 覆盖旧工程迁移、当前版本 round-trip 和未来版本拒绝；`MediaPoolTests` 覆盖渲染状态恢复、dirty 状态和相对路径 fallback。

### 阶段 9.3（已完成）：轨道管理

- 时间线工具栏的“新增轨道”菜单可分别新增视频轨和运动数据轨；视频轨保持在下层，运动数据轨保持在上层，并分别按 `V1/V2…`、`O1/O2…` 自动命名。
- 轨道头可直接重命名，空白名称不会生效；名称、启用状态和锁定状态都随工程 JSON 保存。
- 眼睛按钮控制轨道启用/禁用；禁用轨在时间线上变暗，预览和导出继续共用 `isEnabled` 过滤语义。
- 锁定轨隐藏片段裁剪手柄并阻止移动、裁剪、分割、删除、拖入素材和删除空轨；解锁后恢复编辑。
- 空视频轨和空运动数据轨都可删除；锁定空轨必须先解锁。新增、删除、重命名、启用/禁用、锁定/解锁全部支持 Undo/Redo。
- `MediaPoolTests` 覆盖运动数据空轨堆叠与命名、Undo/Redo，以及轨道状态修改和锁定空轨保护。

### 阶段 9.4（已完成）：同类轨道间移动片段

- 片段拖动同时读取横向时间位移和纵向轨道位移；拖动过程中片段跟随鼠标，目标轨以轻量底色提示，松开后完成换轨。
- 视频片段只能进入视频轨，运动数据片段只能进入运动数据轨；锁定轨和不同类型轨道不会接收片段。
- 目标轨已有片段时继续使用既有 `nonOverlappingStart` 规则，把片段放入距离鼠标落点最近的可容纳空隙；不会覆盖或推开原片段。
- 换轨保持片段 ID、素材引用、`sourceIn`、时长、布局、距离单位和选中态；源轨变空后保留为空轨，由用户决定是否删除。
- 一次横向加纵向拖动合并为同一个“移动片段”Undo/Redo 步骤，预览和导出继续直接读取更新后的轨道顺序。
- 自动测试覆盖视频换轨、运动数据换轨、目标轨冲突避让、锁轨/跨类型拒绝、轨道命中计算和 Undo/Redo。

### 阶段 9.5（已完成）：可见吸附与轻量多选

- 移动片段时同时比较片段头、片段尾与时间线开始、播放头、其他片段边缘，选择阈值内最近的候选；裁剪手柄使用相同来源解析。
- 命中吸附时显示贯穿轨道区的黄色参考线，并标注“时间线开始 / 播放头 / 片段边缘”；松开鼠标立即隐藏。
- 按住 Command 点击片段可追加或取消选择；所有选中片段都有选中描边，点击空白时间线清空选择，检查器继续显示最后选中的主片段。
- ⌘B 会分割播放头下的全部选中片段；⌫ / ⇧⌫ 可批量普通删除或波纹删除，并把整批操作作为一个 Undo/Redo 步骤。
- `StudioModelTests` 覆盖片段头尾吸附及来源解析；`MediaPoolTests` 覆盖多选、批量分割、批量删除和选择状态的 Undo 恢复。

### 阶段 9.6（已完成）：逐片段视频方向与画布适配

- `TimelineVideoCompositionBuilder` 不再把第一段视频的 transform 套给整条组合轨；每个最终可见片段使用独立 `AVMutableCompositionTrack` 和 `AVMutableVideoCompositionInstruction`。
- 每个片段分别读取自己的 `naturalSize` 与 `preferredTransform`，在统一输出画布中等比缩放并居中；未覆盖区间由黑色 instruction 填充。
- 时间线预览的 `AVPlayerItem` 和合成导出的 `AVAssetReaderVideoCompositionOutput` 使用同一份 video composition，因此方向、比例和黑边语义一致。
- 单片段覆盖完整导出范围时仍走原有直接读取路径，保持既有性能；多片段/稀疏路径继续逐帧流式读取。
- 实际写出测试使用 96×48 横屏红色视频和带 90° transform 的竖屏绿色视频连续组合，在 96×96 输出中逐点验证横屏上下黑边、竖屏左右黑边和颜色方向正确。

### 阶段 9.7（已完成）：素材恢复与破坏性操作收口

- 离线素材按文件不存在、权限不足、媒体不可读和格式无效显示具体原因；失败的 relink 保留原素材 URL、片段引用和工程几何。
- 视频和运动素材重新链接成功后可整体撤销/重做，稳定素材 ID、片段 ID、布局、波形和解析后的运动序列随同恢复。
- 自定义时间线确认切换活动源，以及确认移除被时间线引用的素材，都作为单个 Undo/Redo 步骤恢复媒体池、时间线、选中态和当前活动源。
- 普通片段删除、波纹删除和空轨删除继续立即执行并依靠 Undo 恢复；这是与主流剪辑软件一致的轻量交互，不新增高频确认弹窗。
- `MediaPoolTests` 覆盖被引用素材删除、运动素材 relink、无效格式原因及确认替换活动源的 Undo/Redo。

## 里程碑结论

阶段 4 至 9 的时间线规划与收尾验收均已完成，没有遗留的基础时间线开发项。下面的手动 QA 清单保留为以后发布版本的回归矩阵；若继续产品开发，应另立新里程碑（例如转场、画中画或更高规格输出），不要把它们混回本轮收口范围。

## 手动 QA 清单

### 基础工作流

1. 分别多选导入两个视频和两个 FIT/GPX，确认每一批都按 Finder 选择顺序自动加入时间线；第二批从已有工程末尾顺延。
2. 再用“加入时间线”重复加入一个视频和一个运动素材，确认它们从整个工程末尾追加，并分别复用 V1 和现有 overlay 轨。
3. 把视频和运动片段移动成开头、中间和结尾都有空隙的分散片段；再从媒体池拖到对应轨道的指定相对位置，确认拖放仍按落点寻找最近可容纳空隙。
4. 连续新增 V2、V3，把视频从媒体池分别拖入目标轨并与 V1 重叠；确认播放头进入重叠区时显示最高轨视频，离开后恢复下层视频的连续源时间。再删除片段使轨道变空后删除该轨，并检查 Undo/Redo；打开包含足够多轨道的工程确认纵向滚动。
5. 新增 O2、O3，分别重命名视频轨和运动数据轨；逐轨检查禁用后预览/导出不再使用该轨，锁定后片段不能移动、裁剪、分割、删除或接收拖放，解锁后恢复；确认锁定空轨不能删除，并检查所有操作的 Undo/Redo。
6. 确认时间线上的每个视频片段都显示波形，无音频的视频不显示伪波形，多个片段复用同一素材时不会重复长时间加载。
7. 分别把视频、运动数据片段上下拖到同类轨道，确认目标轨高亮、片段属性和选中态不变；尝试拖到锁定轨、不同类型轨和已有片段的位置，确认拒绝或落在最近空隙。再检查 Undo/Redo、吸附、检查器起点时间码和预览源时间。
8. 不选择片段时在多条重叠轨道中按 ⌘B，确认播放头下所有未锁定轨都被分割；选中播放头下某个片段后确认只分割该片段；选中远离播放头的片段时确认不会误切其他轨道。
9. 把 `single.*` 视频和运动片段都拖到 0 秒之后，确认开头是空白黑画布；再分别在右侧检查器输入起点时间，确认片段头移动到输入位置且支持 Undo/Redo。
10. 把片段起点输入到同轨已有片段范围内，确认不会重叠，而是落到最近可容纳空隙；锁定轨道后确认时间码编辑器不可用。
11. 调整导出 in/out，确认播放头和预览范围 clamp 正确。
12. 分别导出透明浮层和合成视频。

### 工程恢复

1. 保存 JSON，退出 App，再打开工程。
2. 确认媒体池、轨道、片段几何、片段布局/单位恢复。
3. 修改导出 in/out、运动数据裁切、渲染范围、类型、编码和码率后保存并重开，确认全部恢复；输出目标仍需重新确认。
4. 移动或重命名一个视频和一个运动素材后重新打开，确认媒体池和时间线都显示离线，但其他素材仍可预览。
5. 分别重新链接视频和运动素材，确认素材 ID、片段位置、source in、时长和布局不变，保存工程后再次打开不再离线。
6. 在离线素材仍覆盖导出范围时检查输出页列出具体文件名并禁用对应导出；把导出范围移开后确认无关离线素材不阻塞。

### 导出质量

1. 多浮层透明视频分别覆盖深色、浅色和彩色背景检查 Alpha。
2. 横屏/竖屏、H.264/HEVC、不同分辨率和不同帧率视频连续组合，分别导出 H.264 与 HEVC 合成视频。
3. 在片段边界和上下视频轨覆盖边界前后逐帧检查画面和音频；确认上层覆盖、下层恢复源时间连续，并确认视频空隙为黑帧/静音、浮层仍继续显示。
4. 运行长素材，观察内存不能随时长持续增长。

## 不可突破的边界

- 透明 Alpha 路径保守修改；任何像素缓冲或颜色空间变化都要有自动测试和深浅背景手动验证。
- 所有写出按帧流式处理，禁止缓存整段视频帧、大图或 CGImage。
- `TimelineProject`、工程 JSON 和布局 preset 保持 Codable 向后兼容。
- 预览、App 导出和 CLI 必须共用同一时间映射、片段选择和校验语义。
- 支持新平台或改共享层时，macOS 既有预览、导出、构建和发布流程不得回退。
